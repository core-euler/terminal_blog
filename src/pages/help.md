Эта страница — как `:help` в Neovim: всё, что нужно, чтобы писать посты и менять сайт под себя. Она не пост, поэтому не попадает ни в ленту, ни в RSS. Лежит в `src/pages/help.md`: всё, что здесь описано, можно сразу попробовать на ней самой.

## Быстрый старт

1. Создайте папку поста внутри категории: `src/content/posts/<категория>/<слаг>/`.
2. Положите в неё `index.md` с фронтматтером (шаблон ниже).
3. Запустите `npm run dev` и откройте `http://localhost:4321`. Пост появится в ленте, в дереве слева и в RSS.

```md
---
title: "Заголовок поста"
date: 2026-09-24
description: "Одна-две фразы для ленты, RSS и поисковиков."
tags: [astro, notes]
draft: false
---

Первый абзац. Заголовок первого уровня писать не нужно:
он берётся из title.

## Первый раздел
```

## Структура и адреса

Пост — это папка. Всё, что относится к посту, лежит рядом с его `index.md`: картинки, видео, исходники.

```text
src/content/posts/
└── travel/                  ← категория
    └── autumn-in-tbilisi/   ← слаг поста
        ├── index.md         ← текст
        ├── old-town.jpg
        └── balcony.jpg
```

- **Адрес поста** повторяет путь папки: `/posts/travel/autumn-in-tbilisi/`.
- **Категория** — это просто папка. Новая папка сразу появится в дереве, настраивать ничего не надо.
- **Дерево слева** строится из настоящих папок, поэтому в нём видны и файлы картинок.
- **Удалить пост** — удалить его папку, больше нигде ничего не остаётся.

## Фронтматтер

Поля проверяются при сборке. Ошибка в них роняет `npm run build` с сообщением, какой файл и какое поле не так.

- `title` — заголовок, непустая строка. Обязательно.
- `date` — дата публикации, например `2026-09-24`. Обязательно. По ней сортируется лента.
- `description` — краткое описание для ленты, RSS и `<meta>`. Обязательно.
- `tags` — список тегов: `[astro, design]`. Необязательно. Каждый тег получает свою страницу `/tags/<тег>/`.
- `draft` — `true` для черновика. Необязательно, по умолчанию `false`.

Любое другое поле считается ошибкой: так опечатка вроде `titel` не проскочит молча.

Если в строке есть двоеточие, её нужно взять в кавычки, иначе YAML сломается. Проще всегда писать `title` и `description` в кавычках.

## Черновики

`draft: true` делает пост черновиком:

- в дереве он помечен `~`, как несохранённый файл;
- в ленту, RSS и на страницы тегов не попадает;
- в `npm run dev` открывается как обычный пост, а в продакшен-сборке его страница не создаётся вовсе.

## Текст

Обычный markdown: абзацы, **жирный**, *курсив*, [ссылки](/), списки, цитаты, `код в строке`.

- **Заголовки.** В теле поста используйте `##` и `###`. Первый уровень уже занят заголовком из `title`. Заголовки `##` и `###` попадают в оглавление справа.
- **Номера строк** в гаттере ставятся сами: абзац считается одной строкой, как в Vim с переносом строк, а в блоках кода нумеруется каждая строка.
- **Блоки кода** подсвечиваются в цветах текущей темы. Укажите язык после трёх обратных кавычек: `ts`, `css`, `bash`, `md` и так далее.

## Картинки

Картинка кладётся в папку поста и вставляется относительным путём:

```md
![Старый город на закате](./old-town.jpg)
```

- Подходят `png`, `jpg`, `webp`, `avif`, `gif`.
- При сборке картинки сжимаются в `webp`, получают размеры и ленивую загрузку. Исходник можно класть большим.
- Текст в квадратных скобках — описание для тех, кто картинку не видит. Не оставляйте его пустым.
- Картинка занимает ширину колонки текста.

## Видео

Видео лучше гифок: весит в разы меньше и не портит цвета. Файл кладётся в папку поста, вставляется HTML-тегом:

```html
<figure>
  <video src="./loop.mp4" autoplay loop muted playsinline width="960" height="540"></video>
  <figcaption>Подпись под видео</figcaption>
</figure>
```

- `autoplay` работает только вместе с `muted`, а `playsinline` нужен для iPhone.
- `width` и `height` — исходный размер ролика. Браузер заранее оставит под него место, и текст не будет прыгать при загрузке.
- Поддерживаются `mp4` и `webm`. Сделать короткий зацикленный ролик без звука можно так: `ffmpeg -i in.mov -t 4 -an -c:v libx264 -crf 28 -movflags +faststart loop.mp4`.

## Цвет текста

Запись `:цвет[текст]` красит кусок строки. Цвет задаётся именем, а оттенок берётся из текущей темы: переключите тему в строке статуса, и цвета поменяются.

- :red[red] — `:red[текст]`
- :orange[orange] — `:orange[текст]`
- :yellow[yellow] — `:yellow[текст]`
- :green[green] — `:green[текст]`
- :cyan[cyan] — `:cyan[текст]`
- :blue[blue] — `:blue[текст]`
- :purple[purple] — `:purple[текст]`
- :pink[pink] — `:pink[текст]`
- :dim[dim] — `:dim[текст]`, приглушённый текст

Внутри работает разметка: :green[**жирный** и `код`]. Вместо короткой записи можно писать HTML: `<span class="c-red">текст</span>`.

Что не станет цветом: время `10:30`, `config:prod`, неизвестное имя вроде `:foo[текст]`. Такой текст остаётся как есть.

Цвет лучше беречь для акцентов. Длинный абзац пастельным цветом на тёмном фоне читать тяжело, поэтому основной текст всегда цвета `text` темы.

## ASCII-арт

Арт пишется в блоке кода с языком `ascii`. Пробелы сохраняются как есть, шрифт моноширинный, внутри работает та же запись цвета:

````md
```ascii alt="Кот"
   /\_/\
  ( :yellow[o].:yellow[o] )
   > :pink[^] <
```
````

Результат:

```ascii alt="Кот"
   /\_/\
  ( :yellow[o].:yellow[o] )
   > :pink[^] <
```

- `alt="…"` — описание для скринридеров. Без него арт от них скрыт, как декоративный.
- Внутри цветного куска `]` пишется как `\]`, а обратный слэш — как `\\`. Вне цветных кусков оба символа пишутся как обычно, так что `/\_/\` можно не трогать.
- На телефоне помещается около 40–45 символов в ширину. Более широкий арт прокручивается по горизонтали.
- Весь блок в гаттере получает один номер строки.

### Эффекты

Слово после `ascii` включает анимацию:

- `wave` — по символам бежит градиент из цветов темы. Раскрашенные куски сохраняют свой цвет.
- `pulse` — арт плавно гаснет и зажигается.
- `blink` — мигает, как курсор.

```ascii wave alt="Надпись help"
 _          _
| |__   ___| |_ __
| '_ \ / _ \ | '_ \
| | | |  __/ | |_) |
|_| |_|\___|_| .__/
             |_|
```

### Покадровая анимация

Строка `%%` делит арт на кадры, `fps=N` задаёт скорость (от 1 до 30, по умолчанию 6). Кадры могут быть разной высоты, короткие дополнятся пустыми строками.

````md
```ascii fps=4 alt="Спиннер"
:cyan[|] загрузка
%%
:cyan[/] загрузка
%%
:cyan[-] загрузка
%%
:cyan[\\] загрузка
```
````

```ascii fps=4 alt="Спиннер"
:cyan[|] загрузка
%%
:cyan[/] загрузка
%%
:cyan[-] загрузка
%%
:cyan[\\] загрузка
```

Анимация сделана на чистом CSS, без JavaScript. Если в системе включено «уменьшение движения», все эффекты останавливаются, а у покадровой анимации остаётся первый кадр.

## Темы и размер текста

**Для читателя.** В строке статуса справа есть выбор темы и три кнопки размера текста. Выбор запоминается в браузере и применяется сразу при загрузке, без вспышки. Без JavaScript этих переключателей нет, сайт показывается в теме по умолчанию.

**Для автора.** Всё задаётся в `src/styles/themes.ts`:

- `DEFAULT_THEME` — тема по умолчанию.
- `THEMES` — список тем. Catppuccin берётся из пакета `@catppuccin/palette`, остальные — из тем Shiki, которыми подсвечивается код.
- **Новая тема из Shiki** — одна строка, например `fromShiki('github', githubDark)` плюс импорт `@shikijs/themes/github-dark-default`. Список готовых тем: `ls node_modules/@shikijs/themes/dist`.
- `roles` у темы — из каких цветов её палитры брать ссылки, активный файл и теги, если стандартные не подходят (например, в Rosé Pine нет зелёного).
- `FONT_SIZES` — три размера текста и их масштаб.
- `TEXT_COLORS` — имена цветов для записи `:цвет[…]`.

У каждого акцентного цвета одна роль: ссылки, активный файл в дереве, теги. Даты и метаданные — приглушённый цвет. Слои интерфейса отличаются яркостью фона, а не линиями.

## Настройки сайта

- `src/site.config.ts` — название, описание, автор (имя, подпись, ссылка) и язык.
- `astro.config.mjs` — адрес сайта в `site`, он нужен для RSS и канонических ссылок. Здесь же подключены markdown-плагин и темы подсветки кода.
- `public/favicon.svg` — иконка вкладки.

## Где что лежит

- `src/content/posts/` — посты.
- `src/content.config.ts` — схема фронтматтера.
- `src/pages/` — страницы: лента, пост, теги, RSS, 404 и эта справка.
- `src/layouts/Editor.astro` — «окно редактора»: дерево, таб, буфер, оглавление, строка статуса.
- `src/components/` — дерево файлов, оглавление, строка статуса, список постов.
- `src/lib/tree.ts` — построение дерева из папок.
- `src/lib/markdown-color.ts` — запись цвета и блоки `ascii`.
- `src/integrations/post-media.ts` — видео рядом с постом.
- `src/styles/` — темы, оформление интерфейса и текста.

## Команды

```bash
npm run dev      # сайт с автообновлением на localhost:4321
npm run build    # сборка в dist/, падает на ошибках во фронтматтере
npm run preview  # посмотреть собранный dist/
```

Если после правки markdown-плагина, тем подсветки или `astro.config.mjs` посты выглядят по-старому, Astro показывает их из кэша. Остановите `npm run dev`, удалите кэш и запустите снова:

```bash
rm -rf node_modules/.astro .astro/data-store.json
```
