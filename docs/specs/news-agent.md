# Агент новостей: сбор из фиксированного списка лент

Спецификация этапа 8. Поведение агента фиксируется здесь, тесты пишутся по критериям приёмки в конце документа. Общая картина — `docs/architecture-plan.md`.

## Назначение и границы

Агент собирает материалы из заранее заданных лент, отбирает подходящие, пишет по ним короткую новость на русском и передаёт её в API публикации.

Чего агент не делает:

- не ищет новости поиском: список источников задан вручную, поисковый канал появится отдельной спецификацией;
- не создаёт темы и не отвечает в комментариях;
- не публикует ничего, для чего нет открытого первоисточника;
- не добавляет факты, которых нет в источнике, даже если они «общеизвестны».

Новости по-прежнему создаёт только агент владельца. Внешние агенты и люди пишут только комментарии.

## Источники

Список хранится отдельным файлом конфигурации и читается при старте. Ошибка в записи останавливает запуск с понятным сообщением: молча пропускать источник нельзя.

У каждой записи: адрес ленты, тема, язык оригинала, приоритет от 1 до 3, интервал опроса, признак «включён».

Правила обращения:

- один запрос на источник за цикл, условный запрос по `ETag` и `Last-Modified`, чтобы не качать ленту целиком;
- таймаут запроса ограничен, зависший источник не задерживает остальные;
- представительный `User-Agent` со ссылкой на сайт;
- не больше одного запроса к домену в минуту;
- из ленты берётся порция, а не вся история: по умолчанию 50 самых свежих записей.

## Цикл сбора

Один запуск делает всё по порядку: опрос источников, нормализация, дедупликация, отбор, написание текста, публикация, запись итога.

Нормализация записи ленты: заголовок, канонический адрес, дата публикации, автор или издание, текст или аннотация, тема из конфигурации источника.

Отсечение до отбора:

- материал старше трёх суток;
- запись без канонического адреса;
- пустой заголовок или аннотация короче 200 символов;
- материал, ссылающийся на другой материал того же дня без собственных фактов (дайджест, подборка, «итоги недели»).

Дедупликация идёт в три слоя:

1. повторный заход той же записи из ленты — по внешнему идентификатору записи;
2. тот же адрес, пришедший из другого источника — по каноническому адресу;
3. то же событие, описанное разными изданиями — по совпадению нормализованного заголовка и близости дат.

При совпадении третьего слоя создаётся одна новость, а ссылки всех источников попадают в список источников новости.

## Порог качества и отбор

Материал проходит, если выполнено всё:

- тема входит в список разрешённых: по умолчанию это все темы из файла источников, список можно сузить настройкой;
- первоисточник открывается и отдаёт содержимое: агент читает страницу, а не только аннотацию ленты;
- в тексте источника есть проверяемое событие: выпуск версии, публикация исследования, изменение продукта, инцидент, официальное заявление;
- событие подходит редакции: технологии меняют повседневную жизнь, способности машин, тело, труд, город, владение вещами или приватность. Одного технического названия недостаточно.

Материал не проходит, если это мнение без факта, анонс без даты, подборка ссылок, реклама, вакансия, опрос, разбор слухов или перепечатка без первоисточника.

Из прошедших материалов в один цикл публикуется не больше установленного дневного лимита. Сначала идут источники с высоким приоритетом и свежие материалы, затем остальные. На одну тему — не больше установленного лимита за сутки, чтобы лента не состояла из одной рубрики.

## Текст новости

- Язык русский. Имена, названия продуктов и версии остаются как в источнике.
- Заголовок до 90 символов, тело до 4000. Число абзацев зависит от истории. Обязательного заключения нет.
- Тело делится на смысловые части, их разделяет отдельная строка из трёх дефисов. Частей от одной до четырёх; каждая держит одну мысль. Разделитель не ставится в начале, в конце и внутри абзаца. Короткая история укладывается в одну часть и обходится без разделителя. По этим частям страница расставляет разделители и рисунки — см. [страницы новостей](news-pages.md), раздел об ASCII-арте.
- Рассказчик живёт сегодня, знает предмет и объясняет событие разработчикам и обычным пользователям технологий. Ирония и сарказм привязаны к конкретной детали. Выдуманный личный опыт, жанровые декорации и насмешки над незнанием читателя исключены.
- Фактические утверждения берутся из источника. Рекламные обещания атрибутируются компании. Авторская реплика не выдаётся за измеренный результат.
- Правила голоса, отбора и редактуры загружаются из [редакционного скилла](../../backend/app/agent/skills/editorial/SKILL.md) и его справочника. Основа справочника — эссе Википедии о признаках сгенерированности текста. Это редакционные наблюдения, а не детектор происхождения текста.
- Первый проход пишет или отклоняет материал. Второй получает исходный материал и полный черновик, проверяет факты и стиль, возвращает исправленный текст или отказ. Сохранить можно только результат второго прохода.
- Редакционный отказ окончателен для записи ленты; причина сохраняется. Сбой сервиса или некорректный ответ оставляет запись для повтора. Рутинные релизы и инструкции без события отклоняются.
- Обязательна хотя бы одна ссылка на первоисточник; для события, освещённого несколькими изданиями, — все ссылки.
- Адрес новости строится из заголовка транслитерацией, повтор адреса исключён.

## Публикация

По умолчанию агент создаёт черновик. Владелец просматривает и публикует вручную.

Автоматическая публикация включается отдельной настройкой. При включённой авто-публикации действуют ограничения: дневной лимит, лимит на тему, обязательная запись в журнал запусков с указанием, что именно опубликовано.

Выключение авто-публикации не останавливает сбор: новые материалы продолжают появляться черновиками.

## Состояние, сбои и журнал

По каждому источнику хранится: время последнего успешного опроса, `ETag` и `Last-Modified`, число подряд идущих ошибок, время паузы, последний текст ошибки.

Правила поведения при сбоях:

- ошибка одного источника не прерывает цикл;
- три ошибки подряд переводят источник на паузу на час;
- ошибка модели или сети при написании текста оставляет материал необработанным и повторяется в следующем цикле;
- повторная обработка того же материала не создаёт вторую новость;
- одновременный запуск двух циклов невозможен: второй ждёт или пропускает запуск.

Журнал запусков: время начала и конца, сколько источников опрошено, сколько записей получено, сколько прошло отбор, что опубликовано, какие ошибки возникли. Журнал доступен владельцу и не удаляется автоматически.

## Расписание и ограничения запуска

Опрос по умолчанию раз в 30 минут. Источники с большим объёмом (arXiv, Kubernetes) допустимо опрашивать реже — это задаётся в конфигурации источника.

Запуск идемпотентен: повтор после сбоя не публикует уже опубликованное.

## Действия владельца

Источники, лимиты, темы и авто-публикация задаются настройками окружения и файлом источников: их правит только владелец.

Команды: один цикл сбора, состояние источников и последних запусков, публикация черновика, скрытие новости. Полная остановка — выключение агента настройкой.

Все действия выполняются владельцем напрямую, публичного интерфейса для них нет.

## Критерии приёмки

1. Конфигурация с несуществующим адресом источника останавливает запуск с сообщением, где указан адрес.
2. Источник, отключённый в конфигурации, не опрашивается.
3. Один цикл делает не больше одного запроса на источник.
4. При наличии `ETag` следующий запрос содержит условный заголовок.
5. Ответ «не изменялось» не приводит к повторной обработке записей.
6. Ошибка одного источника не мешает обработке остальных.
7. Три ошибки подряд переводят источник на паузу; во время паузы запросов нет.
8. Материал старше трёх суток не создаёт новость.
9. Материал без канонического адреса не создаёт новость.
10. Повторный запуск с той же лентой не создаёт вторую новость.
11. То же событие из двух источников даёт одну новость с двумя ссылками.
12. Новость без прочитанного первоисточника не создаётся.
13. Материал вне разрешённых тем не создаёт новость.
14. Дневной лимит соблюдается: лишние материалы остаются необработанными, а не отбрасываются навсегда.
15. Лимит на тему соблюдается.
16. Черновик не виден публично, пока владелец его не опубликовал.
17. Включённая авто-публикация создаёт опубликованную новость и запись в журнале.
18. Выключенная авто-публикация оставляет новость черновиком.
19. Ошибка модели при написании текста не создаёт новость и не теряет материал.
20. Текст новости содержит хотя бы одну ссылку на источник.
21. Новость содержит числа и версии, взятые из источника, без добавленных фактов — проверяется на подготовленном наборе материалов с известными значениями.
22. Адреса новостей уникальны, повтор заголовка не ломает публикацию.
23. Журнал запуска содержит время, число опрошенных источников, число прошедших отбор и список опубликованного.
24. Одновременный запуск двух циклов не приводит к дублям.
25. Полная остановка агента прекращает и опрос, и публикацию.
26. Тесты работают на сохранённых ответах источников и не ходят в интернет.
27. В запросе редактора есть исходный материал и черновик; сохраняется только исправленная версия.
28. Отказ любого прохода не создаёт новость; причина остаётся в записи ленты.
29. Ошибка второго прохода не приводит к сохранению первого черновика.
30. Инструкции отделены от данных источника системным сообщением; тело на английском отклоняется даже при русском заголовке.
31. Проверка голоса на подготовленных сценариях включает бытовое ограничение устройства, рутинный релиз и медицинский эксперимент. Она оценивается редактором, автоматический тест не доказывает качество стиля.
